# Traceability Matrix

## Purpose

Link business outcomes to system requirements and verification evidence.

## Scope

Initial Milestone 1 business objectives and Milestone 2 requirements.

## Actors

Product, engineering, QA, clinical governance, security, and operations.

## Requirements

| Business objective | System requirement | Verification artefact |
| --- | --- | --- |
| Improve access | FR-PATIENT-001, FR-PATIENT-002, FR-PATIENT-003 | Registration and consultation acceptance tests |
| Build trust | FR-DOCTOR-001, FR-ADMIN-001, Security Requirements | Provider verification and audit tests |
| Support continuity | FR-DOCTOR-002, FR-AGENT-001 | Copilot review and journey-workflow tests |
| Reduce administration | FR-ADMIN-002, appointment and notification use cases | Workflow and delivery tests |
| Operate responsibly | FR-AI-002, FR-AI-003, FR-AGENT-002, NFRs | Safety, privacy, and approval evidence |

## Assumptions

Backlog items, tests, and releases will retain requirement IDs.

## Constraints

Traceability does not replace clinical, legal, or security approval.

## Future considerations

Maintain this matrix automatically from requirement, test, and delivery tools.
